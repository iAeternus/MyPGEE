# 408 操作系统大题总结

## PV 操作

**模型**

- 临界资源：一次只允许一个进程访问。
- 信号量：整型变量 $S$，初值为资源数。
  - `P(S)`: $S = S - 1$；若 $S < 0$，阻塞。
  - `V(S)`: $S = S + 1$；若 $S \le 0$，唤醒一个进程。

**方法**

1. 确定资源数，写出信号量初值。
2. 按代码流程分析 $P/V$ 操作。
3. 跟踪队列中阻塞/唤醒情况。
4. 注意：避免死锁（循环等待、不可抢占）。

**真题例**

> 两类进程共享一台打印机，写出 PV 操作。

- 信号量 `mutex=1` 控制互斥；
- 信号量 `empty=1` 控制打印机是否空闲。
- 解法套路：分析资源 → 写初值 → 逐步模拟。

## 银行家算法

**模型**

- 资源分配表：`Max`、`Allocation`、`Need=Max-Allocation`。
- 安全性检查：
  - `Work=Available`；
  - 找到一个进程 $i$，满足 `Need[i] ≤ Work`；
  - 分配完成后 `Work = Work + Allocation[i]`；
  - 重复直到所有进程完成。

**方法**

1. 建立 3 张表。
2. 按步骤检查是否有安全序列。
3. 若请求资源，先判断 `Request ≤ Need`，再判断 `Request ≤ Available`。

**真题例**

> 给出资源表，问是否安全。

- 写出 Need；
- 跟踪 Work 变化；
- 输出安全序列。

## 逻辑地址转物理地址

**模型**

- **分页**：
  - 逻辑地址 = $(页号, 页内偏移)$；
  - 物理地址 = `页表[页号] + 页内偏移`。
- **分段**：
  - 逻辑地址 = $(段号, 段内偏移)$；
  - 物理地址 = `段表[段号].基址 + 偏移`，需检查越界。

**方法**

1. 分页：逻辑地址 ÷ 页大小，得页号和页内偏移。
2. 分段：先检查段内偏移 ≤ 段长，再加基址。
3. 画表法：先列出页表/段表，再计算。

**真题例**

> 页大小 1KB，逻辑地址 2500。

- 页号 = $2500 ÷ 1024 = 2$；
- 偏移 = $2500 \bmod 1024 = 452$；
- 查表 → 算物理地址。

## 段页式管理

**模型**

- 二级结构：段表 + 页表。
- 逻辑地址 = $(段号, 页号, 页内偏移)$。
- 物理地址 = `段表[段号] → 页表基址 + 页号 → 页框号 + 页内偏移`。

**方法**

1. 分解逻辑地址 → 段号、页号、偏移。
2. 查段表 → 页表起始地址。
3. 查页表 → 页框号。
4. 拼接物理地址。

**真题例**

> 段长不同，逻辑地址超出段长要报错。

## 页面置换算法

**模型**

- 页面置换背景：当发生缺页中断而内存已满，需要淘汰一页 → 置换算法决定淘汰哪一页。
- 目标：尽量降低缺页率。
- 常考算法：
  1. FIFO（先进先出）
     - 按进入内存的先后顺序淘汰最早进入的。
     - 优点：实现简单。缺点：可能出现 Belady 异常（页框数增多反而缺页率增大）。
  2. LRU（最近最久未使用）
     - 淘汰最久没用过的页面。
     - 近似实现：用访问位或链表。
  3. OPT（最佳/理想算法）
     - 淘汰未来最长时间不会用的页面。
     - 理论最优，但实际不可实现，只用于比较标准。
  4. CLOCK（时钟/二次机会算法）
     - 用环形队列+访问位。扫描：访问位 = 1 → 清零再给一次机会；访问位 = 0 → 淘汰。

**方法**

1. 准备表格：横轴写页面访问序列，纵轴画出页框。
2. 按算法规则逐步填表：
   - FIFO：队列。
   - LRU：每次选最久没用过的。
   - OPT：每次往后看，找最久不用的。
   - CLOCK：模拟指针移动。
3. 统计缺页次数 → 计算缺页率。

> 注意点：
>
> - 考试时最容易出错的地方：LRU 要一直往前看，OPT 要往后看。
> - FIFO 有 Belady 异常，LRU/OPT 没有。

**真题例**

> 页面访问序列：7, 0, 1, 2, 0, 3, 0, 4，页框数 = 3。

- FIFO：按照进入顺序淘汰。缺页数 = 6。
- LRU：淘汰最久没访问的。缺页数 = 5。
- OPT：看未来访问，淘汰未来最晚被访问的。缺页数 = 4。

## 文件的分配方式

**模型**

文件存储在磁盘上，需要分配物理块。主要方式有：

1. 连续分配
   - 每个文件占据连续的物理块。
   - 文件控制块（FCB）只需存起始块号和长度。
   - 优点：随机访问快，寻道少。
   - 缺点：外部碎片，扩展困难。
2. 链接分配
   - 隐式链接：每个块的末尾存下一个块号。
     - 优点：支持动态增长。
     - 缺点：随机访问慢，指针占空间。
   - 显式链接（FAT 文件分配表）：把指针集中放在内存的 FAT 表里。
     - 优点：随机访问较快。
     - 缺点：FAT 占内存。
3. 索引分配
   - 每个文件有一个索引块，存放所有数据块号。
   - 适合随机访问。
   - 扩展方式：
     - 直接索引：文件块数少时，索引块直接存。
     - 一级索引：索引块指向数据块。
     - 多级索引：索引块指向二级索引块，再到数据块。
     - 混合索引：直接 + 一级 + 二级混合。

**方法**

1. 确认文件大小、磁盘块大小，计算文件需要多少块，$所需块数 = \lceil 文件大小 ÷ 块大小 \rceil$

2. 根据分配方式，确定存储结构：

   - 连续分配：直接找起始块号。
   - 链接分配：按指针追踪，或查 FAT。
   - 索引分配：看索引表指向哪几个块。

3. 考点：计算 存储效率、随机访问第 i 块所需磁盘访问次数。

**真题例**

> 文件大小 12KB，磁盘块 1KB，采用索引分配。

- 文件需要 $12 ÷ 1 = 12$ 块。
- 索引表至少需要 12 项，每项存 1 块号。

> 若采用二级索引，问“访问第 300 块数据需要几次磁盘访问？”

- 第一次：读索引表。
- 第二次：读二级索引块。
- 第三次：读数据块。
- 答案 = 3 次。

## 位示图

**模型**

- 每一位代表一个磁盘块：0 = 空闲，1 = 已分配。

**方法**

1. 按逻辑块号找对应位。
2. 空闲块分配：扫描 0。
3. 释放块：改为 0。

**真题例**

> 第 200 块对应第几字节第几位？

- 字节号 = $200 ÷ 8$；位号 = $200 \bmod 8$。

## 缓冲区耗时计算

**模型**

- 单缓冲：CPU 和 I/O 串行；$T = T_{CPU} + T_{IO}$。
- 双缓冲：并行，$T = \max(T_{CPU}, T_{IO})$。
- 循环缓冲：多个缓冲池，提高吞吐率。

**方法**

1. 分清数据块数。
2. 第一块串行，其余并行。
3. 套公式。

**真题例**

> 单缓冲处理 10 块数据。

- 总时间 = $10 \times (T_{CPU}+T_{IO})$。

> 双缓冲处理 10 块数据。

- 总时间 = $T_{CPU}+T_{IO}+(9 \times \max(T_{CPU},T_{IO}))$。

## 磁盘题

**模型**

- 磁盘调度：FCFS, SSTF, SCAN, C-SCAN。
- 平均寻道长度、平均响应时间。

**方法**

1. 列出磁头初始位置。
2. 按算法顺序访问请求序列。
3. 画轨迹图 → 算总移动距离。

**真题例**

> 初始磁头 50，请求队列 30, 70, 90, 10。

- SSTF：先选最近的请求。
- SCAN：像电梯一样来回扫。
